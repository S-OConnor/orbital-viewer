🛰 Orbital LOS Viewer

Frequently Asked Questions

General

What does "LOS" stand for?

Line of sight. The viewer's satellite POV mode renders the geometric line-of-sight picture from the primary satellite — a 170° fisheye nadir view wide enough to show space around Earth's limb.

Does it display real satellite data?

It displays whatever its inputs feed it. The bundled simulator produces synthetic or CSV-scripted data; the DIS input mode can ingest live IEEE 1278.1 Entity State PDUs from a real simulation exercise. The celestial background (Sun, Moon, planets, bright stars) is astronomically computed from the state message's timestamp to roughly arcminute–half-degree accuracy.

Does it need internet access?

No — never at runtime. All imagery and data are vendored or first-party. Network access is needed only once at build time to download the pinned open-dis-cpp tarball (and that can be mirrored for air-gapped hosts).

How many objects can it handle?

5,000 tracked objects per update cycle (kMaxTrackedObjects), the protocol-level cap, at 1 Hz. This is a design ceiling chosen so the whole pipeline stays simple: one WebGL points draw, one ~450 KB JSON broadcast. olv_sim --generate 5000 load-tests exactly this limit.

Security & deployment

Why is there no TLS or authentication?

By explicit design decision, recorded in the plan and README: the project is scoped to trusted localhost/LAN deployments. UDP and WebSocket are plaintext. Do not expose the ports to untrusted networks; put a reverse proxy or VPN in front if you must cross one. What the backend does defend against is malformed input: every packet is fully validated (structure, CRC, NaN/Inf, range, staleness) before it can touch state.

Do the containers run as root?

The backend and simulator containers run as a dedicated non-root user (UID/GID 10001, nologin). The frontend container uses the stock nginx:alpine-slim image's default user. Images are Podman-friendly and rootless-compatible.

Usage

The page loads but the globe is empty — why?

Almost always a WebSocket mismatch: open Settings and confirm host/port point at a running olv_backend (default localhost:8765). If the status panel shows "stalled", the backend is unreachable or not broadcasting. Full checklist: Troubleshooting.

Can I open frontend/index.html directly from disk?

No. The frontend uses ES modules, which browsers block from file:// origins. Serve it over HTTP — scripts/serve_frontend.sh, the frontend container, or any static file server.

Can it update faster than 1 Hz?

Yes, within limits: the simulator accepts --rate up to 50 Hz and the backend broadcast rate (--broadcast-hz) up to 60 Hz. 1 Hz is the protocol's nominal target and what the UI's staleness heuristics assume; the integration test runs at 2 Hz.

OLV1 or DIS — which input mode should I use?

Use OLV1 (the default) with the bundled simulator: it is lossless and carries confidence, intensity, star types, and highlight flags. Use DIS when interoperating with existing IEEE 1278.1 tooling. DIS mode has documented, deliberate losses: object ids become FNV-1a folds, confidence/intensity are fixed at 100/0, and the STAR category cannot be expressed (degrades to DEBRIS). See the DIS reference.

Can the backend listen for OLV1 and DIS at the same time?

No — the input source is a boot-time choice (--input-mode / [input] mode). Exactly one input source exists per process. Run two backend instances on different ports if you need both simultaneously.

Development

Why no Three.js / React / toml++ / Catch2?

Dependency minimalism is a core design goal (auditable, air-gap friendly). The scene is simple enough for a small first-party WebGL renderer; the config format needs only scalars and one table level; the test framework is ~120 lines. Each first-party replacement is deliberately less general than the library it avoids.

Do I need Node.js to run the frontend?

No. Node ≥ 18 is used only to run the frontend's logic tests and the integration test's parser check. The frontend itself is served as static files and runs entirely in the browser.

Where are the authoritative protocol specs?

In the repository: docs/PROTOCOL_UDP.md, docs/PROTOCOL_DIS.md, docs/PROTOCOL_WS.md — with the further rule that the reference implementations (include/olv/protocol.hpp, src/dis_input_source.cpp, src/json_writer.cpp) win over prose if they ever disagree. This site's reference pages summarize them.

Are simulator runs reproducible?

Yes. The synthetic generator uses a fixed-seed LCG (default seed 1, settable with --seed) and is never seeded from time. Two runs with the same seed, rate, and duration produce identical packet streams.
