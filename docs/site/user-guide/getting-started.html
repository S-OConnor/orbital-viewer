Getting Started

A beginner-friendly first run, two ways. If you haven't installed anything yet, do Installation first.

First run — containers (recommended)

  1. From the repository root, run (add --sim so there's something to see — without it, only the backend and frontend come up and the page waits for real input): 
    scripts/run_all.sh --sim
  2. Watch the output. Expected sequence (assumes scripts/build_all.sh has already built the localhost/olv-backend/localhost/olv-sim images at least once — see Installation — since run_all.sh doesn't compile anything unless you also pass --build): 
    == compose engine: podman compose -p olv -f .../containers/compose.yaml ==
== starting backend + frontend + simulator (ws=8765 udp=47000 http=8000) ==
== waiting for backend on port 8765 ....

Orbital LOS Viewer is running (containerized):
  Frontend:    http://localhost:8000/
  WebSocket:   ws://localhost:8765
  UDP (host):  127.0.0.1:47000   (published; simulator->backend is internal)
  Simulator:   replaying example_mission.csv

Open http://localhost:8000/ in a browser. The frontend defaults to
WebSocket port 8765; if you passed --ws-port, set the new port under Settings.

Streaming container logs — press Ctrl-C to stop and tear the stack down.
    (Exact wording may differ — e.g. Docker instead of Podman — but the key line is that the backend came up and the URLs are printed.)
  3. Open http://localhost:8000/.

What you should see

  • Globe: textured Earth with day/night terminator and a 15° graticule.
  • Connection panel: green status, WebSocket URL, and a "latest data time" that updates every second.
  • Stats panel: UDP received/accepted counting up at ~1 Hz, WS clients: 1, and an object count around 25.
  • Objects panel: a filterable list of debris, satellites, comets, stars, and ground-hot objects from the example mission.
  • Satellite panel: live ECEF position, speed (~7.6 km/s), and altitude (~550 km).

Press Ctrl-C in the terminal when done — the stack stops and removes itself.

First run — binaries you built

Build them first — see Installation: Building the binaries (scripts/build_builder.sh builds the olv-builder image, scripts/build.sh compiles inside it and stages the binaries into build/dist/). Then three processes in three terminals (all from the repo root):

# Terminal 1 — backend
build/dist/backend/bin/olv_backend --udp-port 47000 --ws-port 8765 --log-file olv_backend.log

# Terminal 2 — simulator, replaying the example mission on loop
build/dist/simulator/bin/olv_sim --csv tools/simulator/data/example_mission.csv --rate 1 --loop

# Terminal 3 — static file server for the frontend
scripts/serve_frontend.sh 8000

Then open http://localhost:8000/frontend/ (note the /frontend/ path — the dev server serves the repo root so the About modal's links into docs/ resolve).

Expected terminal output:

  • Backend: silent on stdout by default; check olv_backend.log for a startup line and later client connected events. (Add --log-level debug to also log each accepted packet.)
  • Simulator: a per-cycle progress line (suppress with --quiet); on exit, a summary like done: cycles=61 packets=61 bytes=... send_errors=0.

Configuration walkthrough (5 minutes)

Let's move the WebSocket to port 9000 to see the config system end to end.

  1. Copy and edit the example config: 
    cp config/backend.toml my-backend.toml
# edit: [network] ws_port = 9000
build/dist/backend/bin/olv_backend --config my-backend.toml
  2. Reload the frontend. The status panel shows a stalled/disconnected state — it is still trying port 8765.
  3. Open Settings (gear icon), set WebSocket port to 9000, and click Reconnect. The status turns green. Your choice persists in localStorage across reloads.
  4. Try a typo: change ws_port to ws_prt in the file and restart the backend — it refuses to start and names the bad key (error: my-backend.toml: unknown key "network.ws_prt"). That strictness is deliberate.

Five things to try next

  1. Satellite view: press V (or click SAT) for the 170° fisheye nadir view from the satellite; press again to return.
  2. Trails: Settings → Show trails, slide duration to 60 s — watch orbits streak.
  3. Sky: Settings → Show sky is on by default — find the Moon (with its illuminated %) and planet labels; they are placed for the actual message timestamp.
  4. Selection: click any object on the globe or in the list — it highlights in both places.
  5. Load test: stop the simulator and run build/dist/simulator/bin/olv_sim --generate 5000 --rate 1 — 5,000 objects, the protocol maximum. The object list caps at 1,000 rows and says "showing 1000 of 5000".

Verification steps

# 1. Everything green?
scripts/test.sh

# 2. Is the backend accepting packets? (watch the log)
tail -f olv_backend.log        # expect: accepted seq=... (at debug level)

# 3. Is JSON flowing? Capture two frames with the probe (built but not
#    installed, so it stays in the CMake build tree):
build/container/olv_ws_probe --host 127.0.0.1 --port 8765 --count 2 \
    --timeout 10 --out /tmp/frames.jsonl
head -c 300 /tmp/frames.jsonl  # expect {"type":"hello",... then {"type":"state",...
