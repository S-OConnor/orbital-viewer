Usage

Every major feature: the viewer UI, the simulator, the backend, DIS mode, and automation. Flag-by-flag tables live in the Command-Line Reference.

The viewer

View modes

  • 3D (orbit) — default. Drag to orbit the camera, scroll to zoom.
  • SAT — first-person from the primary satellite: boresight fixed at nadir (Earth's center), screen-up along the velocity vector, rendered as a 170° equidistant fisheye so the full Earth disc plus surrounding space is visible. The satellite's own marker/trail/label are hidden in this mode. If no satellite data has arrived yet, the badge reads "awaiting satellite data" and the orbit view is used.

Toggle with the 3D/SAT control (top right) or V. A badge (top left) confirms the mode. The choice persists across reloads.

Selection & labels

  • Click an object on the globe (12 px hit radius; a >5 px drag is treated as camera movement, not a click) or click a row in the object list. Selection draws a ring and highlights the row.
  • Show labels (Settings) labels the nearest 200 objects, the satellite, and the current selection. Sun, Moon, and planet labels are independent of this cap; off-screen Sun/Moon get edge chevron locators.

The left panel collapses with its toggle button (collapse state is not persisted).

Settings (persisted to localStorage)

  • Trails on/off + duration slider (0–60 s)
  • Labels on/off
  • Sky (stars, Moon, planets) on/off — on by default
  • Per-category visibility toggles (debris / star / comet / satellite / ground-hot / unknown — "unknown" covers OLV1 object records whose type byte doesn't match a known category; the decoder normalizes rather than rejects them)
  • WebSocket host + port with a Reconnect button
  • Reset to defaults — returns to the site-config-merged baseline

The simulator (olv_sim)

CSV mission replay

./build-docker/tools/simulator/olv_sim --csv tools/simulator/data/example_mission.csv --rate 1 --loop

Rows sharing a time_s value form one update cycle; the satellite state carries forward into frames without an explicit sat row. With --loop the mission repeats (sequence numbers keep increasing, so the backend never sees the wrap as stale). CSV column format: File Formats.

Synthetic generation (load testing)

./build-docker/tools/simulator/olv_sim --generate 5000 --rate 1 --duration 0   # forever
./build-docker/tools/simulator/olv_sim --generate 500 --seed 42 --duration 60  # reproducible minute

Generates one primary satellite (550 km, 53° circular LEO) plus N objects with a fixed category mix (~70% debris, 10% satellites, 10% ground-hot, 5% comets, 5% stars). Runs are deterministic for a given --seed (default 1).

Destination, pacing, chunking

./build-docker/tools/simulator/olv_sim --generate 1000 --dest 192.168.1.20 --port 47000 \
    --rate 2 --chunk 24
  • --dest accepts an IP or hostname (e.g. the compose service name backend).
  • --rate: 0 < Hz ≤ 50; the protocol target is 1.
  • --chunk caps objects per packet (max 128). Lower it (~24) to keep datagrams under one Ethernet MTU and avoid IP fragmentation on real networks.

The backend (olv_backend)

./build-docker/olv_backend --udp-port 47000 --ws-port 8765 \
    --log-file olv_backend.log --log-level info
  • Broadcasts a snapshot every second (change with --broadcast-hz, up to 60) — even when no data has arrived yet.
  • Objects not refreshed for 15 s are pruned (--expiry-seconds, 1–3600).
  • --quiet stops mirroring log lines to stderr; the file always gets them.
  • Stop with Ctrl-C (SIGINT/SIGTERM) — the log records a clean shutdown.

DIS input mode

Ingest IEEE 1278.1 Entity State PDUs instead of OLV1:

# 1. Edit config/backend.toml: uncomment dis_satellite_entity_id (required,
#    no CLI flag exists for it) and optionally dis_exercise_id.
./build-docker/olv_backend --config config/backend.toml --input-mode dis

# 2. Any DIS source on port 47001 now feeds the display. The bundled simulator
#    can emit DIS itself:
./build-docker/tools/simulator/olv_sim --generate 100 --protocol dis

Semantics worth knowing (full detail: DIS reference):

  • The entity matching dis_satellite_entity_id (format site:application:entity) becomes the primary satellite; all others become tracked objects.
  • EntityType (kind, domain) maps to categories: space platforms → satellite, land platforms/lifeforms → ground-hot, munitions → comet, everything else → debris. Confidence is fixed at 100, intensity at 0.
  • Non-Entity-State PDUs and filtered exercises are counted as received but not as dropped — so in DIS mode received ≥ accepted + dropped is normal on a busy exercise network.

WebSocket probe (olv_ws_probe)

A capture client for scripting and diagnosis — grabs N JSON frames to a file:

./build-docker/olv_ws_probe --host 127.0.0.1 --port 8765 \
    --count 6 --timeout 30 --out frames.jsonl
# one frame per line; exit 0 on success, 1 with "timeout (captured X of N)" otherwise

Automation examples

# Nightly soak: 5,000 objects for an hour, then assert zero unexpected drops
./build-docker/olv_backend --ws-port 8765 --log-file soak.log --quiet &
./build-docker/tools/simulator/olv_sim --generate 5000 --duration 3600 --quiet
grep -c "dropped" soak.log        # expect 0

# Capture one snapshot for external processing
./build-docker/olv_ws_probe --host 127.0.0.1 --port 8765 --count 1 \
    --timeout 10 --out snap.jsonl && python3 -c \
    "import json;d=[json.loads(l) for l in open('snap.jsonl')];print(d[-1]['stats'])"

# Validate captured frames with the real frontend parser (Node >= 18)
node frontend/tests/validate_message.mjs frames.jsonl --min-objects 100

# Regenerate SBOMs after a dependency change
python3 scripts/gen_sbom.py --out sbom/

# Stop everything containerized + stray processes
scripts/cleanup.sh
