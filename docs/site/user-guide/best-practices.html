Best Practices

Recommended workflows

  • Demos and operations: use the containers. scripts/run_all.sh gives you readiness waiting, port remapping, log streaming, and one-keystroke teardown. Reserve the native three-process flow for development.
  • Pin configuration in files, not flags. Put deployment settings in backend.toml / simulator.toml (they're strict, so drift is caught at startup) and keep CLI flags for one-off experiments. The precedence order — defaults < file < flags — makes this layering safe.
  • Version-control your configs and missions. TOML configs and mission CSVs are small, deterministic inputs; keeping them in git makes any display reproducible.
  • After any change, run the pyramid: ctest --test-dir build, then node --test "frontend/tests/*.test.mjs". The integration test alone proves the full pipeline.

Performance recommendations

  • Stay at 1 Hz unless you need more. The whole design is sized for 1 Hz; higher --rate/--broadcast-hz multiplies JSON serialization (~450 KB per broadcast at 5,000 objects) and client parse work linearly.
  • Chunk below the MTU on real networks. The default 128 objects/packet yields ~6.2 KB datagrams that will IP-fragment on standard Ethernet; fragments multiply loss probability. --chunk 24 keeps packets under ~1,300 bytes. On loopback, the default is fine.
  • Trails are the most expensive render feature. With 5,000 objects and 60 s trails, the trail buffer rebuild dominates frame time on weak GPUs — shorten the duration or disable trails on low-end display machines.
  • Slow clients handle themselves. The per-session outbox drops frames past 5 pending rather than stalling the broadcaster — one struggling wall display cannot back-pressure the rest.
  • Keep the log level at info in production. debug writes a line per accepted packet (40/s at full load) and the logger flushes every line by design.

Security considerations

Scope first: OLV has no TLS and no authentication by design. It is built for trusted localhost/LAN segments. Treat that as a hard boundary, not a default to harden later.
  • Never expose 47000/udp, 47001/udp, or 8765/tcp to untrusted networks. Anyone who can reach the UDP port can inject track data (validation stops malformed packets, not well-formed lies); anyone who can reach the WebSocket can read the world state.
  • Need remote viewing? Put the WebSocket and HTTP ports behind a TLS-terminating, authenticating reverse proxy or a VPN. Leave the UDP intake strictly LAN-side.
  • Use the audit log. Every drop is logged with source address and reason; a burst of bad_magic/bad_crc from an unexpected address is your tamper signal. Consider shipping the log to your normal collection.
  • Exercise networks: set dis_exercise_id. On shared DIS segments this filters foreign exercises at the door.
  • Supply chain: regenerate SBOMs (scripts/gen_sbom.py) when dependencies change and feed them to your scanner (CycloneDX 1.5 — Grype/Trivy/Dependency-Track all accept it). The open-dis tarball is sha256-pinned; keep it that way in mirrors.

Deployment recommendations

  • Prefer rootless Podman. The images already run as non-root (UID 10001); rootless Podman removes the daemon attack surface too.
  • Remap ports via environment, not compose edits. OLV_HTTP_PORT/OLV_WS_PORT/OLV_UDP_PORT change only host publishing; container-internal wiring stays fixed and tested.
  • Mount configs read-only. The compose file carries a commented example for mounting backend.toml; use it rather than baking configs into images.
  • One data source per backend instance. The OLV1 staleness check assumes a single monotonic sequence stream; two simulators aimed at one backend will mutually stale each other. Run one backend per source (distinct ports).
  • Air-gapped sites: mirror the open-dis tarball (OLV_OPEN_DIS_TARBALL/OLV_OPEN_DIS_URL), an apt mirror, and the two base images; after that the stack builds and runs fully offline. Checklist: Installation.
  • Know what's ephemeral. The backend holds no persistent state — a restart is always safe and always clean. The only client-side persistence is browser localStorage settings.

Data-source hygiene

  • Keep mission CSVs deterministic and comment-annotated (# lines are allowed); regenerate the bundled example only via scripts/make_example_csv.py so it stays reproducible.
  • Use OLV1 when you control both ends (lossless); accept DIS's documented degradations (fixed confidence/intensity, folded ids, no stars) only when interoperating with standard tooling — see the DIS reference.
  • Send velocity whenever you have it (HAS_VELOCITY): the sat-view's screen-up vector and the velocity vector display both use it.
