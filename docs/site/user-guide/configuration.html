Configuration

All three components read optional TOML files; commented examples that match the built-in defaults live in config/ and frontend/config.toml. This page explains the model and the recommended settings; the exhaustive key-by-key tables are in the Configuration Reference.

The configuration model

ComponentFileHow it's loadedOn bad config
Backendconfig/backend.toml olv_backend --config config/backend.toml Strict — startup aborts with the offending key + line
Simulatorconfig/simulator.toml olv_sim --config config/simulator.toml Strict — same
Frontendfrontend/config.toml fetched relative to the page at startup Lenient — console.warn + built-in defaults

Precedence is always: built-in defaults < config file < explicit overrides. For the C++ binaries the overrides are command-line flags (applied last regardless of argument order); for the frontend they are the user's saved Settings in localStorage.

Strictness matters: the backend and simulator reject unknown keys, wrong types, and out-of-range values at startup so typos can't hide. E.g. misspelling udp_port as upd_port is a hard error, not a silent default.

The TOML subset

Files are parsed by a small first-party TOML subset parser (backend/include/olv/toml.hpp, mirrored in frontend/js/toml.js). Supported: comments, blank lines, one level of [tables], bare keys, double-quoted strings, integers, floats, booleans. Rejected with a line-numbered error: arrays, dotted keys, dates, hex/octal/binary, underscores in numbers, single-quoted and multi-line strings, inline tables, duplicate keys. Details: File Formats.

Backend configuration

A complete backend.toml showing every key at its default (all keys optional; the two commented DIS keys are only needed in DIS mode):

[network]
udp_bind = "0.0.0.0"      # OLV1 UDP listen address
udp_port = 47000          # OLV1 UDP listen port (1-65535)
ws_bind  = "0.0.0.0"      # WebSocket listen address
ws_port  = 8765           # WebSocket listen port (1-65535)

[broadcast]
hz = 1.0                  # snapshot broadcast rate (0 < hz <= 60)

[state]
expiry_seconds = 15       # prune objects not refreshed within N seconds (1-3600)

[logging]
file   = "olv_backend.log"  # log file path (non-empty)
level  = "info"             # debug | info | warn | error
stderr = true               # mirror info+ lines to stderr

[input]
mode = "olv1"             # "olv1" (default) or "dis"
dis_bind = "0.0.0.0"      # DIS listen address (dis mode only)
dis_port = 47001          # DIS listen port
# dis_exercise_id = 1             # optional filter 0-255; unset = accept all
# dis_satellite_entity_id = "1:1:1"  # REQUIRED in dis mode; "site:app:entity"
DIS mode gotcha: dis_satellite_entity_id has no CLI flag. Running --input-mode dis without a config file that sets it is a startup error. The entity whose DIS EntityID matches all three parts becomes the primary satellite.

Simulator configuration

[target]
host = "127.0.0.1"        # UDP destination (IP or hostname, e.g. "backend")
port = 47000              # destination port (DIS default: 47001)

[source]
mode = "csv"              # "csv" or "generate"
csv_path = "simulator/data/example_mission.csv"
loop = false              # replay repeatedly (csv mode)
generate_count = 100      # synthetic objects, 1-5000 (generate mode)
duration_seconds = 120    # stop after N seconds; 0 = forever (generate mode)
seed = 1                  # deterministic generator seed, 0-4294967295

[send]
rate_hz = 1.0             # update rate, 0 < rate <= 50
chunk = 128               # max objects per packet, 1-128 (olv1 only)
protocol = "olv1"         # "olv1" or "dis"
dis_exercise_id = 1       # DIS emission: exercise id (0-255)
dis_site = 1              # DIS emission: site id (0-65535)
dis_satellite_entity_id = "1:1:1"  # DIS emission: satellite EntityID

[output]
quiet = false             # suppress per-cycle console line

Frontend configuration

frontend/config.toml sets site defaults — the values a fresh browser (no saved Settings) starts with. A user's saved Settings always win, and "Reset to defaults" returns to the config-file-merged baseline.

[websocket]
host = ""                 # "" = use the page's hostname
port = 8765

[display]
show_trails = false
trail_seconds = 30        # 0-60
show_labels = false

Only these five keys are recognized from the file. The remaining settings (showSky, view mode, per-category visibility) are user-side settings in the Settings panel, persisted to localStorage under olv.settings.v1. A missing or invalid config.toml is never an error — the page logs a warning and continues with defaults.

Recommended settings by scenario

ScenarioRecommendation
Single-machine demo Defaults everywhere. Containers: just scripts/run_all.sh.
Backend on another LAN host Leave ws_bind = "0.0.0.0"; set the frontend's websocket.host to the backend host (or let users set it in Settings). Open 47000/udp + 8765/tcp on the backend's firewall.
DIS exercise ingest [input] mode="dis", set dis_satellite_entity_id to the exercise's satellite entity, and set dis_exercise_id to filter a shared network. Consider logging.level = "debug" initially to see filtered/ignored PDU lines.
Load / soak testing Simulator --generate 5000 --duration 0; consider backend logging.level = "warn" to keep the log small (accepted-packet lines are debug-level anyway).
Slow client displays Keep broadcast.hz = 1.0; the per-session outbox drops frames beyond 5 pending, so slow clients degrade gracefully without config.
