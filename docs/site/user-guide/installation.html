Installation

Two paths: containers (fastest — nothing to install beyond Podman/Docker) or building from source. Both are covered end to end below.

Prerequisites

For the container path

  • Podman (with podman compose or podman-compose) or Docker (with docker compose or docker-compose). scripts/run_all.sh auto-detects whichever is present, in that order; override with the OLV_COMPOSE environment variable.
  • Internet access on first build (base images + apt packages + the open-dis-cpp tarball), or the air-gap mirrors below.

Installing system dependencies

# Debian / Ubuntu
sudo apt install g++ cmake libboost-dev

# Fedora
sudo dnf install gcc-c++ cmake boost-devel

# Immutable/Atomic distros (Bazzite, Silverblue, ...) via Homebrew/Linuxbrew
brew install cmake boost

Installing open-dis-cpp (one time)

The one compiled third-party dependency. It is not vendored — build and install it once into a prefix:

scripts/install_open_dis.sh --prefix ~/.local    # or /usr/local, /opt/open-dis

The script downloads the pinned v1.2.0 release tarball, verifies its SHA-256 before compiling, builds only the self-contained dis6 tree (static, -O2), and installs headers plus libopendis6.a and the upstream LICENSE. CMake automatically searches /usr/local, /opt/open-dis, and ~/.local; any other prefix needs -DOLV_OPEN_DIS_PREFIX=DIR at configure time.

Note: the container build runs this script itself — if you only use scripts/run_all.sh, there is nothing to install here.

Building from source

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# verify
ctest --test-dir build --output-on-failure          # backend + sim units, integration
node --test "frontend/tests/*.test.mjs"             # frontend logic tests (optional)

Binaries land at their per-subdirectory defaults:

  • build/olv_backend — the server
  • build/olv_ws_probe — test-support WebSocket capture client
  • build/tools/simulator/olv_sim — the simulator

Useful configure options (details in Build System):

OptionDefaultEffect
-DCMAKE_BUILD_TYPERelease (when unset)optimization level

-DCMAKE_PREFIX_PATH=$(brew --prefix)—find Homebrew-installed Boost (usually automatic)

There is no make install / packaging step: the deliverables are the two binaries plus the static frontend/ directory.

Container installation

The one-liner

scripts/run_all.sh
# then open http://localhost:8000/

This brings up all three services from containers/compose.yaml — the backend, the simulator replaying the example mission on loop at 1 Hz, and the frontend served by nginx. It builds images on first run, waits until the backend accepts WebSocket connections (up to 30 s), prints the URLs, then streams logs. A single Ctrl-C stops and removes the whole stack.

scripts/run_all.sh --build              # force image rebuild after code changes
scripts/run_all.sh --http-port 9000     # remap published host ports
scripts/run_all.sh --ws-port 9765 --udp-port 48000

Building images manually

podman build -f containers/Containerfile.cpp --target backend   -t olv-backend .
podman build -f containers/Containerfile.cpp --target simulator -t olv-sim .
podman build -f containers/Containerfile.frontend -t olv-frontend .

# or all three via compose (docker compose works identically):
podman compose -f containers/compose.yaml up --build

Image facts: backend/simulator build in a Debian bookworm-slim stage and run as non-root UID 10001; the frontend image is nginx:alpine-slim serving frontend/ at the web root with docs/ mounted so in-app About links resolve. The build context excludes host build artifacts via .dockerignore.

The three OLV_*_PORT variables remap published host ports only; container-internal ports are fixed. run_all.sh sets them from its --*-port flags.

Air-gapped installation

  1. On a connected host, download the open-dis-cpp v1.2.0 tarball (URL inside scripts/install_open_dis.sh) and transfer it.
  2. Point the installer at it: OLV_OPEN_DIS_TARBALL=/path/to/tarball scripts/install_open_dis.sh --prefix ~/.local — the SHA-256 check still runs.
  3. For containers, additionally mirror the apt repos and pre-pull debian:bookworm-slim and nginx:alpine-slim; pass the tarball mirror as --build-arg OLV_OPEN_DIS_URL=....
  4. Nothing else touches the network — at runtime the stack is fully offline.

Verifying the installation

./build/olv_backend --help        # prints usage, exit 0
./build/tools/simulator/olv_sim --help
ctest --test-dir build --output-on-failure

Expected: backend_unit, sim_unit, and integration all pass (integration takes up to ~40 s and requires free ephemeral ports). Next: Getting Started.
