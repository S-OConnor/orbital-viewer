Installation

Everything builds, tests, and runs in containers — the only host prerequisite is Docker or Podman. Bring up the whole stack with one command, or build the binaries yourself inside the same build-environment image. Both are covered end to end below.

Prerequisites

  • Podman (with podman compose or podman-compose) or Docker (with docker compose or docker-compose). scripts/run_all.sh auto-detects whichever is present, in that order; override with the OLV_COMPOSE environment variable. This is the only host requirement — the C++20 toolchain, CMake, Boost ≥ 1.74 headers, and the one compiled third-party dependency (open-dis-cpp v1.2.0) all live inside the olv-builder container image built from containers/Dockerfile.builder.
  • Internet access on first build (base images + dnf packages + the open-dis-cpp tarball, baked into the olv-builder image), or the air-gap mirrors below.

Native build (advanced, unsupported): a native C++20 toolchain (GCC ≥ 12 / Clang ≥ 14), CMake ≥ 3.20, Boost ≥ 1.74 headers, and an OpenDIS CMake package (OpenDIS::OpenDIS6) on CMAKE_PREFIX_PATH also work — see containers/Dockerfile.builder for the exact package list this repo is tested against, and scripts/install_open_dis.sh for what it runs to get open-dis-cpp. This path has no documented step-by-step; the container is the supported workflow.

Building the binaries

# 1. Build the build-environment image once (or pull a prebuilt one — see
#    OLV_BUILDER_IMAGE under Container environment variables below)
docker build -f containers/Dockerfile.builder -t localhost/olv-builder:latest .

# 2. Build + test inside it — binaries land in ./build-docker on the host
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD":/src -w /src localhost/olv-builder:latest \
  sh -c 'cmake -S . -B build-docker -DCMAKE_BUILD_TYPE=Release && cmake --build build-docker -j"$(nproc)" && ctest --test-dir build-docker --output-on-failure'

# frontend logic tests run on the host (optional):
node --test "frontend/tests/*.test.mjs"
With Podman, drop --user — rootless Podman already maps the container's root user to you; add :z to the volume flag on SELinux hosts. ctest passes all three suites inside the image; the integration test's frontend-parser sub-check is skipped there since Node isn't installed in olv-builder (run ctest on the host against the same build-docker tree, where Node is available, to exercise it).

Binaries land at:

  • build-docker/olv_backend — the server
  • build-docker/olv_ws_probe — test-support WebSocket capture client
  • build-docker/tools/simulator/olv_sim — the simulator

They need only glibc and libstdc++ to run (Boost is header-only, open-dis is linked statically), so they run directly on a compatible Linux host with no container involved at runtime; if the host's glibc is incompatible, run them the same way via docker run.

Useful configure options (details in Build System):

-DCMAKE_BUILD_TYPERelease (when unset)optimization level

There is no make install / packaging step: the deliverables are the two binaries plus the static frontend/ directory.

Container installation

The one-liner

scripts/run_all.sh
# then open http://localhost:8000/

This brings up all three services from containers/compose.yaml — the backend, the simulator replaying the example mission on loop at 1 Hz, and the frontend served by nginx. It builds images on first run, waits until the backend accepts WebSocket connections (up to 30 s), prints the URLs, then streams logs. A single Ctrl-C stops and removes the whole stack.

scripts/run_all.sh --build              # force image rebuild after code changes
scripts/run_all.sh --http-port 9000     # remap published host ports
scripts/run_all.sh --ws-port 9765 --udp-port 48000

Building images manually

The build-environment image below is the same olv-builder image used to build the binaries directly in Building the binaries above.

# build-environment image (toolchain + Boost + open-dis-cpp) that backend/simulator
# compile FROM — build once, or point OLV_BUILDER_IMAGE at a registry copy:
podman build -f containers/Dockerfile.builder -t localhost/olv-builder:latest .

podman build -f containers/Dockerfile --target backend   -t olv-backend .
podman build -f containers/Dockerfile --target simulator -t olv-sim .
podman build -f containers/Containerfile.frontend -t olv-frontend .

# or all three via compose (docker compose works identically); this also
# builds olv-builder first via its opt-in profile:
podman compose -f containers/compose.yaml --profile builder build builder
podman compose -f containers/compose.yaml up --build

Image facts: backend/simulator compile in the olv-builder build-environment image (Rocky Linux 10.2 + gcc-c++/cmake/boost-devel/open-dis-cpp) and run in a Rocky Linux 10.2-minimal stage as non-root UID 10001 (no packages installed at runtime — Boost is header-only, open-dis is linked statically); the frontend image is nginx:alpine-slim serving frontend/ at the web root with docs/ copied in alongside it so in-app About links resolve. The build context excludes host build artifacts via .dockerignore.

Air-gapped installation

  1. On a connected machine, build containers/Dockerfile.builder once (mirror the dnf repos, and pass the open-dis-cpp tarball mirror as --build-arg OLV_OPEN_DIS_URL=..., or pre-fetch the tarball and pass it via OLV_OPEN_DIS_TARBALL — see scripts/install_open_dis.sh, which the image runs internally; the pinned SHA-256 is enforced either way), then push the image to an internal registry along with a mirrored rockylinux:10.2-minimal and nginx:alpine-slim.
  2. On the offline machine, pull those images and point the build at them — OLV_BUILDER_IMAGE=harbor.example.com/olv/olv-builder:1.0.0 (and OLV_RUNTIME_IMAGE=... for the runtime base) — see Container environment variables.
  3. Nothing else touches the network — at runtime the stack is fully offline. (A native/advanced build has the same open-dis-cpp tarball requirement; see the note under Prerequisites.)

Verifying the installation

./build-docker/olv_backend --help        # prints usage, exit 0
./build-docker/tools/simulator/olv_sim --help
docker run --rm -v "$PWD":/src -w /src localhost/olv-builder:latest \
  sh -c 'ctest --test-dir build-docker --output-on-failure'

Expected: backend_unit, sim_unit, and integration all pass (integration takes up to ~40 s and requires free ephemeral ports). Next: Getting Started.
