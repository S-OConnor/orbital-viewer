Installation

Everything builds, tests, and runs in containers — the only host prerequisite is Docker or Podman. Bring up the whole stack with one command, or build the binaries yourself inside the same build-environment image. Both are covered end to end below.

Prerequisites

  • Podman (with podman compose or podman-compose) or Docker (with docker compose or docker-compose). scripts/run_all.sh auto-detects whichever is present, in that order; override with the OLV_COMPOSE environment variable. This is the only host requirement — the C++20 toolchain, CMake, Boost ≥ 1.74 headers, and the one compiled third-party dependency (open-dis-cpp v1.2.0) all live inside the olv-builder container image built from containers/Dockerfile.builder.
  • Internet access on first build (base images + dnf packages + the open-dis-cpp tarball, baked into the olv-builder image), or the air-gap mirrors below.

Native build (advanced, unsupported): a native C++20 toolchain (GCC ≥ 12 / Clang ≥ 14), CMake ≥ 3.20, Boost ≥ 1.74 headers, and an OpenDIS CMake package (OpenDIS::OpenDIS6) on CMAKE_PREFIX_PATH also work — see containers/Dockerfile.builder for the exact package list this repo is tested against, and how it builds and installs open-dis-cpp (the OPEN_DIS_* step). This path has no documented step-by-step; the container is the supported workflow.

Note: this open-dis-cpp dependency is only needed for the backend's DIS input mode. The backend's third input mode, OLV2 (--input-mode olv2, OLV2 reference), is plain UDP like OLV1 and adds no third-party dependency at all.

Building the binaries

# 1. Build the build-environment image once (or point OLV_BUILDER_IMAGE at a
#    prebuilt/registry image and skip this — see Container environment
#    variables below)
scripts/build_builder.sh

# 2. Compile + install into build/dist/{backend,simulator} (tests included,
#    Release by default; runs offline, --network none)
scripts/build.sh

# 3. Run the test suite against that build tree (nothing is recompiled)
scripts/test.sh

# frontend logic tests run on the host (optional):
node --test "frontend/tests/*.test.mjs"

# Steps 1-3 (plus packaging, step 4-5 below) in one go, stopping at the
# first failure:
scripts/build_all.sh
scripts/test.sh passes all three suites inside the image; the integration test's frontend-parser sub-check is skipped there since Node isn't installed in olv-builder (run ctest --test-dir build/container on the host against the same build tree, where Node is available, to exercise it). scripts/build.sh --clean deletes build/container and build/dist first; --debug switches to CMAKE_BUILD_TYPE=Debug.

Binaries land at:

  • build/dist/backend/bin/olv_backend — the server
  • build/dist/simulator/bin/olv_sim — the simulator
  • build/dist/simulator/share/olv/data/example_mission.csv — the bundled example mission, staged alongside the simulator
  • build/container/olv_ws_probe — test-support WebSocket capture client; not installed, so it only ever lives in the CMake build tree

They need only glibc and libstdc++ to run (Boost is header-only, open-dis is linked statically), so they run directly on a compatible Linux host with no container involved at runtime; if the host's glibc is incompatible, run them the same way via docker/podman run (the pattern scripts/build.sh itself uses — see scripts/_common.sh's olv_builder_run).

Useful configure options, set via scripts/build.sh's flags or by running cmake directly inside the container (details in Build System):

OptionDefaultEffect
-DCMAKE_BUILD_TYPERelease (scripts/build.sh --debug for Debug)optimization level
-DOLV_BUILD_TESTSONbuild unit tests + enable CTest

-DCMAKE_PREFIX_PATH=DIR—nonstandard open-dis-cpp install location (native build only; not needed inside olv-builder)

Packaging is a separate step (scripts/package.sh, §Container installation) — scripts/build.sh's own deliverable is the staged build/dist/ tree plus the static frontend/ directory.

Container installation

The one-liner

scripts/run_all.sh
# then open http://localhost:8000/

This brings up the backend and frontend from containers/compose.yaml, using the localhost/olv-backend/localhost/olv-sim images already built by the pipeline below (or registry images, if OLV_BACKEND_IMAGE/OLV_SIM_IMAGE point at one) — it never compiles anything itself. It waits until the backend accepts WebSocket connections (up to 30 s), prints the URLs, then streams logs. A single Ctrl-C stops and removes the whole stack.

scripts/run_all.sh --sim                # also start the simulator (replays the
                                         # example mission on loop at 1 Hz)
scripts/run_all.sh --input dis --sim    # DIS input: backend on 47001/udp, simulator sends DIS
scripts/run_all.sh --input olv2 --sim   # OLV2 input: backend on 47002/udp, simulator sends OLV2
scripts/run_all.sh --build              # run scripts/build_all.sh first, then start
scripts/run_all.sh --http-port 9000     # remap published host ports
scripts/run_all.sh --ws-port 9765 --udp-port 48000
Without --sim, only the backend and frontend come up and the page waits for real input — the simulator sits behind the compose sim profile.

--input olv1|dis|olv2 (default olv1) selects the input source. Each mode has a backend + simulator config pair in containers/config/<mode>/, mounted read-only into the containers; edit those files to change a mode's container settings (e.g. the DIS satellite entity ID, which must match on both sides).

Building images manually

The five-step pipeline behind scripts/run_all.sh --build, spelled out (all via scripts/build_all.sh, or run individually):

# 1. build-environment image (toolchain + Boost + open-dis-cpp) — build once,
#    or point OLV_BUILDER_IMAGE at a registry copy:
scripts/build_builder.sh

# 2. compile backend + simulator + tests inside it, stage the runtime files:
scripts/build.sh

# 3. run the test suite against that build tree:
scripts/test.sh

# 4-5. build the backend/simulator runtime images from the staged trees
#    (refuses if build/dist doesn't match the last passing test.sh run):
scripts/package.sh

# frontend image is built by compose itself, from the repo root:
podman compose -f containers/compose.yaml build frontend

Image facts: backend/simulator compile inside the olv-builder build-environment image (Rocky Linux 10.2 + gcc-c++/cmake/boost-devel/open-dis-cpp, via scripts/build.sh, not a Dockerfile RUN) and the runtime images (containers/Dockerfile.backend/Dockerfile.simulator) just COPY the staged binary in, running in a Rocky Linux 10.2-minimal stage as non-root UID 10001 (no packages installed at runtime — Boost is header-only, open-dis is linked statically); the frontend image is nginx:alpine-slim serving frontend/ at the web root with docs/ copied in alongside it so in-app About links resolve. Each build context is scoped to what that image needs — build/dist/backend/, build/dist/simulator/, or the repo root for the frontend — and host build artifacts are excluded via .dockerignore.

The three OLV_*_PORT variables remap published host ports only; container-internal ports are fixed. run_all.sh sets them from its --*-port flags.

Air-gapped installation

  1. On a connected machine, run scripts/build_builder.sh once (mirror the dnf repos, and pass the open-dis-cpp tarball mirror as --build-arg OLV_OPEN_DIS_URL=...; the pinned SHA-256 is still enforced), then push the resulting olv-builder image to an internal registry along with a mirrored rockylinux:10.2-minimal and nginx:alpine-slim.
  2. On the offline machine, pull those images and point the pipeline at them — OLV_BUILDER_IMAGE=harbor.example.com/olv/olv-builder:1.0.0 (and OLV_RUNTIME_IMAGE=... for the runtime base) — then run scripts/build.sh, scripts/test.sh, and scripts/package.sh as usual; all three already run with --network none. See Container environment variables.
  3. Push the resulting olv-backend/olv-sim images with a normal podman tag/push; to run registry images instead of local ones, set OLV_BACKEND_IMAGE/OLV_SIM_IMAGE before scripts/run_all.sh.
  4. Nothing else touches the network — at runtime the stack is fully offline. (A native/advanced build has the same open-dis-cpp tarball requirement; see the note under Prerequisites.)

Verifying the installation

build/dist/backend/bin/olv_backend --help        # prints usage, exit 0
build/dist/simulator/bin/olv_sim --help
scripts/test.sh

Expected: backend_unit, sim_unit, and integration all pass (integration takes up to ~40 s and requires free ephemeral ports). Next: Getting Started.
