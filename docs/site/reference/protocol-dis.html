DIS Input Protocol (IEEE 1278.1 Entity State PDUs)

Normative sources: docs/PROTOCOL_DIS.md, and above it the reference implementation src/dis_input_source.cpp. Enabled with olv_backend --input-mode dis; default port 47001/udp.

General rules

  • Transport UDP, one PDU per datagram (DIS bundling unsupported; trailing bytes after the first Entity State PDU are ignored).
  • Big-endian (network order) — the opposite of OLV1.
  • Decoded with open-dis-cpp v1.2.0 (BSD-2-Clause), DIS 6 class set.
  • DIS world coordinates are geocentric (ECEF) meters and m/s — the same frame as OLV, so positions/velocities pass through numerically unchanged.
  • PDU timestamps are used only for per-entity staleness; the backend stamps its own receive time as lastDataTime.

Accepted PDU subset

Header fieldAcceptedAnything else
protocolVersion (byte 0)5, 6, or 7dropped as malformed
exerciseID (byte 1)all, or the configured dis_exercise_idignored (received-only)
pduType (byte 2)1 = Entity Stateignored (received-only)

Consumed fields: EntityID (site, application, entity), EntityType (kind, domain), entityLocation (3×f64), entityLinearVelocity (3×f32), header timestamp. Orientation, dead reckoning, markings, appearance, and articulation parameters are decoded but unused.

Satellite promotion

DIS has no privileged satellite record, so the required config key dis_satellite_entity_id = "site:application:entity" (three colon-separated decimal uint16s) names it. The entity matching all three parts becomes the primary satellite; everyone else becomes a tracked object. The decision never consults EntityType. Because DIS updates one entity at a time, the last-known satellite state is carried forward into every update (zeroed until first seen). Running mode="dis" without this key — or with a malformed value — is a hard startup error.

EntityID → OLV id (FNV-1a fold)

OLV ids are u32; DIS EntityIDs are 48 bits. Both satellite and object ids use the same deterministic fold: FNV-1a 32-bit over the six bytes site_hi, site_lo, app_hi, app_lo, entity_hi, entity_lo (offset basis 2166136261, prime 16777619). Collisions are a documented limitation, not an error: one WARN per colliding pair, later entity wins — negligible at ≤5000 entities.

Fixed values (no DIS analogue): confidence = 100, intensity = 0.0, flags = HAS_VELOCITY (HIGHLIGHT never set). No mapping produces STAR — DIS cannot express OLV star markers.

Per-entity timestamp staleness

Let ts = timestamp >> 1 (31 MSBs = ticks into the hour; the absolute/relative LSB is ignored for ordering). Keyed by the full 48-bit EntityID:

  1. First PDU from an entity, or ts == 0: accept.
  2. ts ≥ last_ts: accept, update.
  3. ts < last_ts and difference < 230: stale — dropped, counted, debug-logged.
  4. ts < last_ts and difference ≥ 230: hourly wraparound — accept, update.

The shared state layer's OLV1 sequence gate is satisfied by a synthesized, strictly-increasing per-process sequence (one per accepted PDU), so it never self-fires in DIS mode.

Validation order & stats accounting

Every datagram first increments udpReceived. Then, in order:

#ConditionOutcome / log
1length < 12 (PDU header)drop malformed — warn: dropped too_short
2version ∉ {5,6,7}drop malformed — warn: dropped bad_version
3exercise filter mismatchignored — debug: filtered exercise=N (received-only)
4pduType ≠ 1ignored — debug: ignored pdu kind=N (received-only)
5Entity State body fails decodedrop malformed — warn: dropped malformed_body
6per-entity timestamp staledrop stale — debug: dropped stale
7otherwiseaccepted — applied to the state store

Stats identity: OLV1 mode: received == accepted + malformed + stale (exact). DIS mode: received ≥ accepted + malformed + stale — the remainder is unsupported PDU kinds + filtered exercises. No new drop kinds exist in DIS mode.

Configuration keys

[input]
mode = "dis"                        # select DIS intake at boot ("olv1" default)
dis_bind = "0.0.0.0"                # UDP listen address
dis_port = 47001                    # UDP listen port
# dis_exercise_id = 1               # optional filter, 0-255; unset = accept all
dis_satellite_entity_id = "1:1:1"   # REQUIRED in DIS mode

The only DIS-related CLI flag is --input-mode olv1|dis; all dis_* values come from the config file.

Simulator DIS emission (olv_sim --protocol dis)

  • One Entity State PDU per entity per cycle, satellite first, protocolVersion 6, marshaled big-endian.
  • Satellite uses the configured dis_satellite_entity_id; each object's 32-bit OLV id is spread losslessly as application = id >> 16, entity = id & 0xFFFF, with the configured fixed dis_site.
  • Timestamps: 31-bit ticks-into-hour derived from the cycle counter (monotone across CSV loop wraps), relative-flag LSB = 0.
  • EntityType emitted: satellite (1,5), ground_hot (1,1), comet (2,0), debris (0,5); star and any unmapped type fall back to (0,0), since STAR has no DIS row (§5).
  • Round-trip losses (inherent to DIS, by spec): backend-side ids become FNV-1a folds (not the raw OLV ids); confidence/intensity fixed at 100/0.0; STAR degrades to UNKNOWN.
