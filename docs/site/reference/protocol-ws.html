WebSocket JSON Protocol (version 1)

Normative sources: docs/PROTOCOL_WS.md; serializer include/olv/json_writer.hpp + src/json_writer.cpp, parser frontend/js/net.js. Default endpoint ws://<host>:8765/.

Backend → browser only: UTF-8 JSON text frames, one JSON object per frame. Clients never send (input is read and ignored). One hello on connect, then state at the broadcast rate (default 1 Hz) — every tick, even before any UDP data has arrived.

hello (once, immediately after the handshake)

{
  "type": "hello",
  "protocolVersion": 1,
  "serverTime": "2026-07-01T12:34:56.789Z",
  "broadcastHz": 1.0,
  "limits": { "maxObjects": 5000 }
}

Clients MUST reject a protocolVersion other than 1.

state (broadcast at broadcastHz)

{
  "type": "state",
  "serverTime": "2026-07-01T12:34:56.789Z",
  "lastDataTime": "2026-07-01T12:34:56.500Z",
  "satellite": { "id": 1, "seq": 42,
                 "pos": [4126540.2, -4681712.5, 1003432.1],
                 "vel": [1234.56, 2345.67, -6543.21] },
  "objects": [
    [1001, 1, 6923371.4, 12000.0, -55000.2, 7611.0, 0.0, 0.0, 87, 0.0, 0],
    [2001, 5, 1113194.9, -4842330.0, 3985029.2, null, null, null, 95, 1450.0, 1]
  ],
  "stats": { "udpReceived": 480, "udpAccepted": 478, "udpDropped": 2,
             "udpRateHz": 8.0, "wsClients": 1, "objectCount": 2,
             "broadcastSeq": 12 }
}

Field semantics

FieldTypeMeaning
serverTimeISO-8601 UTC, ms backend wall clock at serialization; drives the frontend's scene clock (Sun/Moon/planets/star positions)
lastDataTimeISO-8601 UTC, ms · or null receive time of the last accepted UDP packet; null until first data
satelliteobject · or null primary satellite; seq = sequence of the packet that provided it; pos m ECEF, vel m/s ECEF
objectsarray of 11-element rows all objects not yet expired (15 s default window), sorted by id
stats.udpReceived/Accepted/Droppedcounters totals since backend start; dropped = malformed + stale (see the DIS accounting note)
stats.udpRateHznumberaccepted packets/s over a trailing 5 s window
stats.wsClientsintcurrently connected clients
stats.objectCountintrows in objects
stats.broadcastSeqcounter+1 per broadcast tick

Object row columns (fixed order, 11 columns)

#NameTypeNotes
0idu32—
1catint 0–50 unknown · 1 debris · 2 star · 3 comet · 4 satellite · 5 groundHot; any other integer renders as unknown (forward compatibility)
2–4px, py, pznumberECEF meters, rounded to 0.1 m
5–7vx, vy, vznumber or null m/s rounded to 0.01; all three null when the source sent no HAS_VELOCITY (all-or-none — partial is a parse error)
8confint 0–100confidence %
9intensitynumberKelvin (groundHot), magnitude (star), else 0
10flagsintbit1 (value 2) HIGHLIGHT; bit0 mirrors has-velocity

Row-array encoding is a deliberate size optimization: ~450 KB vs ~800 KB per broadcast at 5,000 objects compared with key/value objects.

Required client behavior

  • Reconnect with backoff (1 s doubling to a 10 s cap — the reference frontend uses 1/2/4/8/10).
  • Treat unknown message types as ignorable (forward compatibility). Note the row shape itself is strict — new columns would be a breaking change.
  • Reject malformed messages: non-JSON, missing/unknown type, missing objects on state, rows of length ≠ 11, non-numeric id/pos, non-integer cat, partial velocity triples. An integer cat outside 0–5 still parses, as unknown. The reference implementation (parseStateMessage) counts errors and keeps the connection alive.
  • Client-side staleness: no state frame for > 3 s → show a stalled-connection indicator.

Server behavior notes

  • The snapshot is serialized once per tick and shared across sessions (shared_ptr<const string>).
  • A session with more than 5 pending frames has new frames dropped (the frame, not the connection), with a rate-limited warning in the log.
  • Connect/disconnect events are logged with the peer endpoint and client count.
