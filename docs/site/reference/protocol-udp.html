OLV1 UDP Protocol (version 1)

Normative sources: docs/PROTOCOL_UDP.md, and above it the reference implementation include/olv/protocol.hpp. This page is a faithful summary.

Little-endian binary datagrams, serialized field-by-field (no struct overlay, no padding). Floats are IEEE 754 binary32/binary64. Coordinates are ECEF meters, velocities ECEF m/s. No timestamp on the wire — receivers stamp arrival time; freshness is sequence-only. Default port 47000/udp.

Update cycles with more than 128 objects are split across packets; every packet is self-contained (satellite state + its chunk + object_total), so loss never corrupts state.

Packet header (STATE_UPDATE, msg_type = 1)

offset size type  field
------ ---- ----  -----------------------------------------------------------
0      4    u8[4] magic            'O','L','V','1'
4      1    u8    version          1
5      1    u8    msg_type         1 = STATE_UPDATE
6      2    u16   hdr_flags        reserved, MUST be 0
8      4    u32   sequence         +1 per PACKET sent (wraps)
12     4    u32   sat_id           primary satellite identifier
16     8    f64   sat_pos_x        ECEF meters
24     8    f64   sat_pos_y
32     8    f64   sat_pos_z
40     4    f32   sat_vel_x        ECEF m/s
44     4    f32   sat_vel_y
48     4    f32   sat_vel_z
52     2    u16   object_count     records in THIS packet, <= 128
54     2    u16   object_total     objects in this update cycle, <= 5000
56     48*N       object records
56+48N 4    u32   crc32            over bytes [0, 56+48N)

Total datagram length MUST equal 56 + 48*object_count + 4 exactly.

Object type enum

ValueNameNotes
1DEBRISorbital debris
2STARdistant direction marker; position = direction × large radius (e.g. 1e12 m); fixed in ECEF (Earth-rotation drift is a documented simplification)
3COMET—
4SATELLITEtracked satellite other than the primary
5GROUND_HOThot surface object; stationary in ECEF

Any other value rejects the whole packet (kBadObjectType).

CRC

CRC-32 IEEE 802.3: reflected, polynomial 0x04C11DB7 (reflected table constant 0xEDB88320), init and final XOR 0xFFFFFFFF — i.e. zlib's crc32. Computed over all bytes before the CRC field. Reference vector: crc32("123456789") = 0xCBF43926.

Ordered validation (receiver MUST, in order)

  1. length < 60 → kTooShort; length > 6204 → kTooLong
  2. magic ≠ OLV1 → kBadMagic
  3. version ≠ 1 → kBadVersion
  4. msg_type ≠ 1 → kBadMsgType
  5. object_count > 128, or object_total > 5000, or count > total → kTooManyObjects
  6. length ≠ 56 + 48·count + 4 → kBadLength
  7. CRC mismatch → kBadCrc
  8. any float NaN/±Inf → kNonFinite
  9. any |position| > 1e13 m → kOutOfRange
  10. unknown object_type → kBadObjectType

State layer (step 11): with last = last accepted sequence, accept iff (int32_t)(sequence - last) > 0 — wraparound-safe; first packet always accepted; duplicates/older drop as stale.

Every failure drops the whole packet (never partial application), is counted per reason, and is logged with the source address. Confidence > 100 is the one soft case: clamped, not rejected.

Versioning rules

  • version bumps on any layout change; receivers reject unknown versions.
  • New msg_type values may be added under version 1; receivers reject unknown types, so deploy receiver support first.
