File Formats

The mission CSV, the TOML subset, the backend log line format, and the generated artifact formats.

Mission CSV (olv_sim --csv)

Parsed by tools/simulator/src/csv_reader.cpp — strict, with line-numbered errors. Blank lines and # comments are allowed; trailing \r is stripped (CRLF-safe). The first non-comment line must be exactly:

time_s,kind,id,type,px_m,py_m,pz_m,vx_mps,vy_mps,vz_mps,confidence,intensity,flags
ColumnRule
time_sfinite double, seconds from mission start; rows sharing a value form one update cycle (frames are sent in ascending time order)
kindsat or obj. The first frame must contain a sat row; later frames without one carry the satellite forward
idu32
typeobjects: 0–5 or a name — unknown, debris, star, comet, satellite, ground_hot; empty → unknown (0); ignored on sat rows
px_m, py_m, pz_mfinite doubles, ECEF meters
vx_mps, vy_mps, vz_mpsall three empty (= no velocity) or all three present; partial triples are an error
confidenceempty → 100; else integer 0–100
intensityempty → 0; else finite float (Kelvin for ground_hot, magnitude for star)
flagsempty → 0; else only 0 or 2 (HIGHLIGHT). The HAS_VELOCITY bit is OR'd in automatically when velocity is present

Number parsing rejects trailing garbage and non-finite values. Example file: tools/simulator/data/example_mission.csv (61 frames, regenerable with scripts/make_example_csv.py).

The TOML subset

Implemented twice, deliberately identically: include/olv/toml.hpp (C++, strict consumers) and frontend/js/toml.js (JS, lenient consumer). Grammar:

SupportedRejected (line-numbered error)
  • comments (#) and blank lines
  • one level of [table] (reopening allowed)
  • bare keys [A-Za-z0-9_-]+
  • double-quoted strings with escapes \" \\ \n \t \r
  • booleans true/false
  • integers and simple floats (no exponent)
  • CRLF line endings
  • arrays and inline tables
  • dotted keys, nested tables
  • single-quoted and multi-line strings
  • dates/times
  • hex/octal/binary numbers, underscores in numbers
  • duplicate keys

Values flatten to "table.key" paths with types string / integer / float / boolean. Consumers layer their own schema on top: the backend/simulator reject unknown keys; the frontend ignores them with a warning.

Backend log format

<ISO-8601 UTC, ms> <LEVEL> [component] message

2026-07-01T12:34:56.789Z INFO  [main] startup udp_bind=0.0.0.0 udp_port=47000 ws_bind=0.0.0.0 ws_port=8765 ...
2026-07-01T12:35:03.001Z WARN  [udp]  dropped bad_crc len=6204 from=10.0.0.7:58211
  • Levels: DEBUG, INFO, WARN, ERROR; components: main, udp, dis, ws.
  • Append-mode file, flushed per line; info+ mirrored to stderr unless --quiet.
  • Grep-friendly stable phrases: startup, accepted seq=, dropped <reason>, client connected / client disconnected, shutting down, clean shutdown, fatal:.

Captured frame files (olv_ws_probe --out)

One JSON text frame per line (JSONL). Line 1 is normally the hello message, subsequent lines state messages. Validate with node frontend/tests/validate_message.mjs FILE [--min-objects N] — it re-parses every line with the production frontend parser and requires at least one state frame with a non-null satellite.

SBOM files (sbom/*.cdx.json)

  • CycloneDX 1.5 JSON, one per shippable artifact: backend.cdx.json (olv_backend + olv_sim; components: Boost with auto-detected version, open-dis-cpp pinned v1.2.0) and frontend.cdx.json (zero code components; two file-type components for the NASA textures with runtime-computed SHA-256).
  • Deterministic serialNumber (uuid5 over fixed namespace); only the timestamp field varies between runs.
  • Consumable by Grype, Trivy, Dependency-Track, etc.

Frontend settings blob (localStorage)

Key olv.settings.v1, a JSON object holding only explicitly-changed settings (defaults are not written). Corrupt JSON is tolerated (defaults win). Schema: see the settings table.
