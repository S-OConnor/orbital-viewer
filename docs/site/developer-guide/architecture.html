Architecture in Depth

The backend's threading and memory model, the input-source strategy seam, error handling, logging, and the frontend's runtime structure. Companion pages: Architecture at a Glance (system level) and the Source Walkthrough (file level).

Backend threading & concurrency model

Exactly two threads, each owning a private Boost.Asio io_context:

  • Thread 1 (input) is spawned by InputSource::start() (src/olv1_input_source.cpp:26 / dis_input_source.cpp:103). Exactly one input source exists per process, chosen by Config::input_mode at boot.
  • Thread 2 (main) runs ioc.run() from main.cpp:75. The Beast acceptor, every session, and the broadcast timer all live on this one thread, so the sessions_ set needs no locking — single-threaded by construction.
  • StateStore (src/state_store.cpp) is the sole synchronization point: one std::mutex guards countReceived, countDropped, apply, and snapshot. The Logger has its own internal mutex and is safe from both threads.
  • Shutdown: an asio::signal_set (SIGINT/SIGTERM) on the main context logs "shutting down", calls ws.stop(), then input->stop() (joins thread 1), then stops the main context — deterministic teardown order, no detached threads.

StateStore::apply — the merge rules

  • Sequence gate (stateful): first packet always accepted; after that, accept iff (int32_t)(seq - last_seq) > 0 — wraparound-safe. This is validation step 11; it lives here, not in proto::decode, because it needs state.
  • Satellite: replaced wholesale on every accepted packet.
  • Objects: upsert by id. Records merge into the table and stamp last_update; objects carry forward across packets until the expiry window (default 15 s) prunes them at snapshot time. A packet never clears objects it doesn't mention — this is what makes chunked and lossy delivery safe.
  • Rate window: accept timestamps are kept for a trailing 5 s window; udpRateHz = count / 5.
  • snapshot(mono) prunes expired objects (boundary value retained, +1 ms pruned), copies everything, and returns objects sorted ascending by id.

The InputSource strategy seam

class InputSource {
 public:
  virtual ~InputSource() = default;
  virtual void start() = 0;   // idempotent; spawns the receive thread
  virtual void stop()  = 0;   // idempotent; joins it
};
std::unique_ptr<InputSource> makeInputSource(const Config&, StateStore&, Logger&);

Both implementations feed the identical countReceived / countDropped / apply API, so the Stats panel means the same thing in both modes. The DIS implementation additionally:

  • parses the 12-byte PDU header manually (version/exercise/type/timestamp) before handing the body to open-dis-cpp's EntityStatePdu::unmarshal (wrapped in try/catch — the library throws on truncation);
  • folds 48-bit EntityIDs to u32 via FNV-1a (collision → one WARN per pair);
  • keeps per-entity newest-timestamp staleness (ts >> 1, hourly wraparound at 230);
  • carries the satellite forward: DIS updates one entity per PDU, but apply() replaces the satellite wholesale — so the last-known satellite state is stamped into every synthesized packet;
  • synthesizes a strictly-increasing sequence per accepted PDU so the OLV1 staleness gate in apply() never self-fires.

Memory ownership

  • Backend: main() owns everything by value or unique_ptr in declaration order — Logger, StateStore, InputSource, io_context, WsServer — so destruction order is the reverse of construction and references passed down (e.g. StateStore& into input sources) outlive their users. Sessions are shared_ptr-owned by the Beast async chain and registered in the server's session set; the broadcast payload is a shared_ptr<const std::string> serialized once per tick and shared by every session's outbox.
  • No dynamic global state. There are no singletons; the test framework's registry is the only static-init pattern in the repo.
  • Frontend: factory functions returning closures (createModel(), createSettings(), createConnection(), createRenderer(), createUi()) — module-level state is avoided; main.js owns all instances and wires callbacks. GL buffers are preallocated for 5,000 objects at renderer creation.

Logging

One line per event, written by the thread-safe Logger (src/logger.cpp), flushed every line:

2026-07-01T12:34:56.789Z INFO  [main] startup udp=0.0.0.0:47000 ws=0.0.0.0:8765 ...
2026-07-01T12:35:02.120Z INFO  [ws]   client connected 127.0.0.1:52344 clients=1
2026-07-01T12:35:03.001Z WARN  [udp]  dropped bad_crc len=6204 from=10.0.0.7:58211
2026-07-01T12:35:04.500Z DEBUG [udp]  accepted seq=42 objs=25 total=25 from=127.0.0.1:41000
  • Levels: debug < info < warn < error; below-threshold lines are dropped. Info+ mirrors to stderr unless --quiet.
  • Components: [main] lifecycle, [udp]/[dis] intake (accepted at debug, malformed at warn, stale/filtered at debug), [ws] connections and outbox overflow.
  • The startup line intentionally appends input_mode=/config_file= only when non-default, keeping the default run byte-identical to pre-DIS versions (regression-tested property).

Configuration system

Both C++ binaries share the same two-pass pattern (src/config.cpp, tools/simulator/src/sim_config.cpp): pass 1 finds --config (order-independent, at most once) and applies the file over defaults; pass 2 applies remaining flags in argv order. The TOML schema is a closed set — every known key has a type check and range check, and anything else is unknown key. Cross-field invariants (e.g. DIS mode requires dis_satellite_entity_id) are checked on the merged result.

Frontend runtime model

  • Boot (main.js): fetch config.toml (lenient) → createSettings(localStorage, siteDefaults) → createRenderer (fatal overlay on failure) → createConnection → createUi → start the requestAnimationFrame loop + 1 s UI tick.
  • Data path: net.js validates every message structurally (row length 11, category 1–5, all-or-none velocity, protocolVersion 1 on hello); model.js stores only the latest snapshot; renderer.setSnapshot and ui.updateData consume it.
  • Reconnect: backoff 1 → 2 → 4 → 8 → 10 s (capped); endpoint changes from Settings reconnect immediately; stale-socket guards make handler races harmless.
  • Scene clock: the renderer anchors an epoch to each snapshot's serverTime and advances it with performance.now() deltas — Sun, Moon, planets, and star GMST all derive from this single clock, which keeps celestial positions correct even if the client's wall clock is wrong.
  • Settings flow: one-way sync store → form; every control writes back via update() (validated/clamped); onChange re-applies renderer settings and reconnects only if host/port changed.

Design patterns in use

  • Strategy — InputSource (OLV1 vs DIS intake).
  • Factory — makeInputSource; all frontend createX() constructors.
  • Snapshot/copy-on-read — StateStore::snapshot() decouples the lock from serialization.
  • Registrar/static-registration — OLV_TEST macro self-registers test cases at static-init.
  • Dependency injection for testability — wsFactory in net.js, storage in settings.js, fetchFn in site_config.js, processDatagram() as the DIS test seam.
  • Lockstep dual implementation — the fisheye GLSL block is a byte-for-byte copy of sat_camera.js math; the TOML grammar exists in C++ and JS. Both are guarded by parallel test suites and loud comments.
