Testing

Three layers: C++ unit tests (first-party framework), frontend logic tests (node:test), and a shell-driven end-to-end integration test — all wired into two commands.

Running everything

ctest --test-dir build --output-on-failure     # backend_unit + sim_unit + integration
node --test "frontend/tests/*.test.mjs"        # frontend logic tests (quote the glob!)
Quote the glob. node --test expands the pattern itself; an unquoted glob can behave differently across shells. The quoted form is the project's canonical invocation.

C++ unit tests

Framework: test/support/olv_test.hpp (~120 lines, zero third-party) — OLV_TEST self-registration, non-fatal OLV_CHECK* macros, --list support. See the API page for macro semantics.

olv_sim_tests (CTest: sim_unit)

CSV happy path and malformed-row handling (each bad field class), frame grouping and satellite carry-forward, chunking edge cases (1, 128, >128), sequence monotonicity, generator determinism, DIS builder marshaling.

Running a single case

./build/olv_backend_tests --list        # enumerate case names
./build/olv_backend_tests               # run all (no per-case filter exists)
ctest --test-dir build -R backend_unit          # via ctest

Frontend logic tests

Eleven suites under frontend/tests/, all DOM-free — they import the pure modules directly under Node ≥ 18:

  • net_parse — every accept/reject path of parseStateMessage; connection status sequencing and reconnect gating with an injected fake WebSocket factory.
  • model, settings, site_config, toml — state, clamping/persistence/precedence, lenient config, grammar acceptance/rejection with line numbers.
  • sun, sky, star_catalog — ephemeris sanity: equinox/solstice declination, GMST ranges, Moon phase, catalog invariants (Sirius/Vega spot checks).
  • sat_camera — view-matrix orthonormality, up-vector fallback chain, fisheye radius/theta/depth math (the JS half of the GLSL lockstep).
  • atlas, textures — frozen constants, painted-cell determinism, POT downsizing math, GL handle lifecycle against a stub GL.
node --test "frontend/tests/*.test.mjs"          # all
node --test frontend/tests/net_parse.test.mjs    # one suite

Integration test (CTest: integration)

scripts/integration_test.sh — the full pipeline on ephemeral random ports (UDP 46000–47999, WS 18000–19999), 120 s CTest timeout:

  1. Writes a backend TOML with a bogus UDP port + debug logging, then overrides the port by CLI flag — proving defaults < file < flags precedence live.
  2. Starts olv_backend, polls the WS port up (50 × 0.2 s).
  3. Runs olv_sim --generate 500 --rate 2 --duration 60.
  4. Captures 6 frames with olv_ws_probe (30 s timeout).
  5. Structural checks ("type":"state", satellite, lastDataTime), then — if Node is present — re-parses every frame with the real frontend parser (node frontend/tests/validate_message.mjs --min-objects 100).
  6. Asserts the backend log recorded accepted packets and a client connected event; prints INTEGRATION PASS.

A cleanup trap kills both processes and removes the temp dir on any exit path.

System & regression testing

  • Renderer smoke test: no automated browser tests exist (no headless browser dependency, by design). frontend/dev/smoke.html is the manual harness: synthetic snapshot at 1 Hz, all five categories, trails + labels + sky on, V/S toggles. Eyeball it after renderer changes, in both view modes.
  • Regression discipline: behavior-preserving refactors are held to byte-identical observable output where feasible — the input-source refactor verified an identical default-run startup log against the pre-feature commit.
  • Determinism as regression tooling: olv_sim --seed N produces identical packet streams; capture frames with olv_ws_probe before and after a change and diff them.

Performance testing

# Protocol-ceiling soak (backend + renderer under max load)
./build/tools/simulator/olv_sim --generate 5000 --rate 1 --duration 600
# Watch: Stats panel rate ~40 pkt/s, no drops in the log, smooth frame rate.

# Faster-than-spec stress
./build/tools/simulator/olv_sim --generate 5000 --rate 4 --duration 60
./build/olv_backend --broadcast-hz 4

There is no automated perf harness or budget; the acceptance bar from the plan is "5,000 objects at 1 Hz renders smoothly on localhost". Use browser DevTools (Performance tab) for frame timing and the Stats panel for pipeline throughput.

Known gaps

  • No automated browser/E2E UI tests (manual smoke.html only).
  • No CI to run any of this automatically — see CI/CD status.
  • ws_server.cpp concurrency (multi-client fan-out, slow-client drops) is exercised only indirectly via the integration test.
