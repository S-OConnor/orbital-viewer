Build System

CMake ≥ 3.20: the top-level CMakeLists.txt sets up the project and finds dependencies, then adds src/, tools/ and test/, each of which lists its own sources and target options. Shared settings live in cmake/common.cmake; tools/simulator/ is independently configurable. The frontend has no build step at all.

Target map

cmake/common.cmake

  • Include-guarded (OLV_COMMON_INCLUDED) so subprojects can bootstrap it standalone.
  • C++20 required, extensions off; CMAKE_BUILD_TYPE defaults to Release when unset.
  • Options: OLV_BUILD_TESTS (default ON — builds test binaries and calls enable_testing()) and OLV_WERROR (default OFF).
  • Homebrew handling: appends $HOMEBREW_PREFIX (or /home/linuxbrew/.linuxbrew) to CMAKE_PREFIX_PATH — this is why Bazzite/Silverblue builds usually work with no extra flags.
  • INTERFACE targets: olv_proto (adds include), olv_test_support (adds test/support), olv_warnings (-Wall -Wextra -Wpedantic [+ -Werror]).

cmake/open_dis_cpp.cmake

Locates the prefix installed by scripts/install_open_dis.sh: search order is -DOLV_OPEN_DIS_PREFIX, then /usr/local, /opt/open-dis, $HOME/.local. On success it defines the imported static target open_dis_cpp with its headers marked SYSTEM (so upstream-generated code doesn't trip our warning set); on failure it stops with a FATAL_ERROR that includes the install instructions.

Subproject layout

  • CMakeLists.txt (top level) — project(), includes cmake/common.cmake, finds dependencies (Threads, find_package(Boost 1.74 REQUIRED CONFIG) — CONFIG mode, required by CMake 4-era Boost packages, header-only usage — and cmake/open_dis_cpp.cmake), adds the subdirectories below, and includes cmake/tooling.cmake (format/format-check/lint).
  • src/CMakeLists.txt — static libs olv_core and olv_net, and the olv_backend executable.
  • tools/CMakeLists.txt — the olv_ws_probe tool, then add_subdirectory(simulator).
  • test/CMakeLists.txt (only when OLV_BUILD_TESTS) — olv_backend_tests (CTest backend_unit) and the integration test (UNIX only): runs scripts/integration_test.sh with the three target file paths, 120 s timeout, label integration.
  • olv_backend, olv_ws_probe and olv_backend_tests set RUNTIME_OUTPUT_DIRECTORY to the build root, so they still land at build/olv_backend etc.; olv_sim lands in build/tools/simulator/.
  • tools/simulator/CMakeLists.txt — olv_sim_lib static lib (everything except main.cpp, so tests link the real code), olv_sim, and olv_sim_tests (CTest sim_unit).
  • tools/simulator/CMakeLists.txt begins with an if(NOT DEFINED PROJECT_NAME) standalone header — you can configure the simulator in isolation: cmake -S tools/simulator -B build-sim; in that mode it finds Threads, Boost and open-dis-cpp itself.

Quality targets

cmake --build build --target format         # clang-format -i over include/src/test/tools
cmake --build build --target format-check   # --dry-run --Werror (CI-suitable)
cmake --build build --target lint           # cppcheck warning/performance/portability, exit 1 on findings

Both no-op with a notice if the tool isn't installed. The format targets carry a Homebrew keg-only HINT path so brew-installed clang-format is found. clang-tidy is configured (.clang-tidy) but not wired into a target — it needs a compilation database:

cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
clang-tidy -p build src/*.cpp tools/simulator/src/*.cpp

Dependency management

  • Boost: system-provided, never vendored (size). Header-only usage means no Boost link libraries and no Boost ABI concerns.
  • open-dis-cpp: pinned v1.2.0, sha256-verified tarball, compiled once into a prefix by scripts/install_open_dis.sh (only the self-contained dis6 tree; builds with -O2 -w -std=c++17; honors CXX/AR; installs LICENSE + provenance). No package manager (vcpkg/Conan) is used anywhere — deliberate, for air-gap simplicity.
  • Frontend: zero dependencies; no npm, no lockfiles.

CTest & CI integration

ctest --test-dir build --output-on-failure            # all three tests
ctest --test-dir build -R backend_unit                # one suite
ctest --test-dir build -L integration                 # by label
No CI pipeline exists yet. Everything a pipeline needs is already a clean, non-interactive command: cmake --build build --target format-check lint, ctest --test-dir build, and node --test "frontend/tests/*.test.mjs". A minimal CI job is literally those three lines after configure (plus scripts/install_open_dis.sh in the image). See Release Process.

Container builds

containers/Containerfile.cpp is a multi-stage build: a build stage (debian:bookworm-slim + g++/cmake/libboost-dev) runs install_open_dis.sh --prefix /usr/local before COPY . . for layer-cache friendliness, configures with -DOLV_BUILD_TESTS=OFF, and builds only olv_backend olv_sim; the backend and simulator runtime targets copy a single binary each into a fresh slim base with a non-root user (UID 10001). Containerfile.frontend is a one-stage nginx:alpine-slim copy of frontend/ and docs/ — no toolchain at all.
