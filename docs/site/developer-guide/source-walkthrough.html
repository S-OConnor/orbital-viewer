Source Walkthrough

The lifecycle of each process and what every major class/module does, in execution order. Pair with the API Documentation for signatures.

Backend lifecycle (olv_backend)

backend/src/main.cpp, top to bottom:

  1. parseArgs() (config.cpp) — two passes: resolve --config first, then apply flags in order. Errors print usage and exit 2; --help exits 0.
  2. Logger::open() — appends to the log file; failure exits 1. A single startup ... INFO line records the effective config (mode/config-file fields appended only when non-default).
  3. Construction (inside one try/catch): StateStore store(expiry) → makeInputSource(cfg, store, log) — the factory returns Olv1InputSource or DisInputSource; the DIS constructor parses the satellite EntityID and binds its socket, so bad DIS config fails here, before threads — → io_context → WsServer(ioc, bind, port, store, log, hz) (binds the TCP acceptor).
  4. input->start() spawns thread 1; ws.start() arms the acceptor + broadcast timer.
  5. signal_set(SIGINT, SIGTERM) — on signal: log, ws.stop(), input->stop() (join), ioc.stop().
  6. ioc.run() — the main thread becomes the WS thread until shutdown; returns → "clean shutdown" → exit 0. Any escaped exception logs fatal: and exits 1.

olv/protocol.hpp — the wire format in one header

  • Constants: magic "OLV1", version 1, header 56 B, record 48 B, max 128 objects/packet, 5000/cycle, packet size 60–6204 B, coordinate bound 1e13 m.
  • ObjectRecord/StatePacket — plain structs; serialization is field-by-field little-endian via detail::putU32/getF64/... helpers (no struct overlay, no alignment traps).
  • crc32() — compile-time table, zlib-compatible; reference vector 0xCBF43926 for "123456789" is unit-tested.
  • encode() truncates >128 objects and clamps confidence/total; decode() runs the ordered DecodeError pipeline (reference) and only fills the output packet on full success.

StateStore

Object table (unordered_map by id), satellite, counters, accept-time ring for the 5 s rate window. Four public methods, each fully locked: countReceived(bytes), countDropped(kind), apply(pkt, wall, mono) (sequence gate → satellite replace → object upsert → timestamps), snapshot(mono) (prune → copy → sort by id). Carry-forward is a property of not clearing: objects persist until expiry, which is what makes 40-packet chunked cycles coherent.

WsServer & sessions

Beast async accept loop; each session does the WebSocket handshake, sends the hello message, then participates in broadcasts. The timer tick calls store.snapshot(), json_writer serializes once into a shared_ptr<const string>, and each session queues it — over 5 pending frames, the frame is dropped for that session with a rate-limited WARN. Client-to-server input is read and discarded (keeps the connection healthy). Connect/disconnect log lines carry the endpoint and client count.

json_writer

Hand-rolled serializer (snprintf floats): positions rounded to 0.1 m, velocities to 0.01 m/s, objects as 11-element row arrays, udpDropped = malformed + stale. Produces hello and state messages exactly as specified in PROTOCOL_WS.

DisInputSource

processDatagram() (public test seam) implements the seven-step DIS pipeline: count → length ≥ 12 → version 5–7 → exercise filter → PDU type 1 → EntityStatePdu::unmarshal (try/catch) → per-entity timestamp staleness → map + apply. Mapping: FNV-1a EntityID fold, EntityType (kind,domain) → category table, fixed confidence 100 / intensity 0 / HAS_VELOCITY. The satellite (matched by full EntityID) is carried forward into every synthesized packet, and a strictly-increasing local sequence keeps the shared staleness gate quiet.

Simulator lifecycle (olv_sim)

  1. parseSimArgs() — same two-pass config/flag model; picks destination port 47001 automatically in DIS mode when no port given.
  2. Source setup: CSV mode — parseCsv() (strict, line-numbered errors) then buildFrames() (group by time_s, satellite carry-forward, first frame must contain a sat row). Generate mode — Generator(count, seed).
  3. Socket: resolve --dest (IPv4 preferred — this is what makes compose service names like backend work), connect the UDP socket.
  4. Send loop: steady_clock pacing at 1/rate; per cycle either buildPackets() (OLV1: chunk ≤128, monotonic sequence, proto::encode) or buildDisPdus() (one big-endian Entity State PDU per entity, satellite first; timestamps derived from the cycle counter so CSV loops stay monotone). Send errors log and count but never abort.
  5. Exit: after CSV pass (unless --loop) or --duration; prints done: cycles= packets= bytes= send_errors=.

Generator details: deterministic LCG (Numerical Recipes constants); primary satellite in a 550 km, 53° circular orbit with analytically exact velocity; object mix 70% debris / 10% satellite / 10% ground-hot / 5% comet / 5% star; stars at 1e12 m fixed directions; ground-hot on the surface at 400–1800 K. Earth rotation is deliberately not modeled.

One render frame (renderer.frame)

  1. Compute the active view: orbit matrices, or the sat-view matrix + fisheye uniforms (fall back to orbit if no satellite).
  2. Draw globe → graticule → (if showSky) stars/Moon/planets on a 300-unit shell with depth writes off → Sun disc → trails → all objects in one GL_POINTS draw → satellite marker + velocity vector (orbit mode only).
  3. 2D overlay pass: selection ring, nearest-200 labels, Sun/Moon/planet labels, off-screen chevrons.

Objects farther than 120 units (120,000 km) are clamped onto a celestial shell direction-preserved, so stars at 1e12 m still render sensibly.
